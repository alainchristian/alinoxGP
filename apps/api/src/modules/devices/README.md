# devices

**Purpose:** GPS trackers: registration (bring-your-own-device path), engine synchronization, installation on vehicles with a permanent history, the device→tenant routing used by ingestion, and (M5b, ADR-0009) onboarding: catalogue model, setup instructions, lifecycle with history, effective capabilities.

**M5b additions.** Endpoints: `PUT /devices/:id/variant`, `GET /devices/:id/configuration`, `POST /devices/:id/configured`, `GET /devices/:id/capabilities` (`devices.capabilities.read`), `GET /devices/:id/history`. Registration accepts an optional catalogue variant (listed models only; IMEI Luhn check when the model uses an IMEI; the simulator profile only with `SIM-` identifiers), firmware, serial, SIM ICCID and the acknowledged consent notice. Lifecycle: with a model → `AWAITING_CONFIGURATION`, without → `REGISTERED`; the customer confirming "configured" → `AWAITING_FIRST_SIGNAL`; the first usable position (pipeline, off the hot path) → `ACTIVE`. One function (`device-lifecycle.ts`) writes the status and the append-only `device_status_history`. **Effective capabilities** (`packages/shared/src/catalogue.ts`) = catalogue ∧ installation ∧ observed; unknown stays unknown, unverified is never shown as verified, remote immobilization is never enabled.
**Owned tables:** `gps_devices` (RLS: visible to the **owner** and to the **operating** organization), `device_assignments` [T] (append-only history: closed rows immutable, never deleted, partial unique indexes = one open assignment per device and per vehicle).
**Endpoints:** `GET/POST /devices`, `GET/PATCH /devices/:id`, `POST /devices/:id/sync`, `POST /devices/:id/assign`, `POST /devices/:id/unassign` — permissions `devices.read`, `devices.register`, `devices.assign`.
**Rules:**
- `uniqueId` (what the tracker transmits) is globally unique; a clash answers a generic `DEVICE_IDENTIFIER_UNAVAILABLE` and writes a platform-visible audit entry — never revealing the other owner.
- `SIM-…` ids are simulated: allowed only in sandbox organizations (API check **and** database CHECK/trigger); `is_simulated` and the prefix can never disagree.
- Registration never depends on the engine: the row is created first, then synced to Traccar; if the engine is unreachable it stays `PENDING` and is retried (reconciliation job / `POST /devices/:id/sync`). The engine-side name is our device id (no customer names in Traccar).
- Unassigning removes the vehicle's live state (it would otherwise show a stale "current" location). History stays.
**Public services:** `DeviceRoutingService.resolve(engineId)` (system DB role; in-process cache whose lifetime is `ROUTING_CACHE_TTL_SEC`, default 300 s, longer than any reporting interval; an assignment change clears the entry on every API instance over Redis pub/sub; hit/miss statistics via `stats()`), `DeviceEngineSyncService.sync(device)`.
**Failure scenarios covered (e2e + DB tests):** other tenant's device (404), cross-tenant assignment attempts, double assignment (409), engine down (PENDING, API stays up), idempotent re-sync, simulated device in a production organization.
