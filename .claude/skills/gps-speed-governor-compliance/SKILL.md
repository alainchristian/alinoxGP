# Speed governor compliance (spec Module 18, milestone M9)

**Context.** Rwanda requires speed governors on public passenger and goods transport vehicles (Presidential Order N° 25/01 of 25/02/2015, art. 30 bis). RURA's *Public Notice on Minimum Requirements for Road Speed Governor Supply and Installation for Public and Goods Transport* (30 July 2020) tells authorised suppliers what their system must do. Our providers who are RURA-authorised suppliers use the platform as the tracking platform and off-board storage system that the notice requires. Read the notice's requirement table in `docs/PROJECT_SPEC.md` Module 18 before building anything here.

Several details are **not known yet** and must not be invented:
- the Annex A data format
- RURA's transmission interface
- retention periods
- which vehicle classes are covered, and their set speeds
- the draft national standard

See spec Appendix B13–B16. Make each one configurable, put it behind a clearly labelled development adapter, and record it in `docs/OPEN_QUESTIONS.md`.

## 1. Who does what

| Party | Responsibility |
|---|---|
| Governor hardware | Limits speed **on the vehicle**: driver buzzer warning, then progressive engine-power reduction at the set speed; failsafe if unplugged. Keeps 72 driving hours of records in non-erasable on-board memory |
| Provider (RURA-authorised supplier) | Holds the authorisation; installs, calibrates, seals and fits the RURA sticker; inspects at least every 6 months; responds to faults; answers to RURA |
| Platform | Stores and relays records in real time; detects violations, tamper and offline periods; alarms the provider; sends the customer SMS; produces quarterly reports; gives RURA read-only access; transmits violations to RURA once the interface exists |
| Regulator (RURA, possibly police) | Read-only access to governed vehicles' compliance data |

**The platform never changes a governor's set speed or calibration remotely, and never sends engine-power commands.** Set-speed changes are made on the vehicle by an authorised technician, then recorded in the platform with who, when and the new value. "Ignition disabling" in RURA's feature list maps only to the stationary starter-inhibit of `gps-immobilization-safety`. A "geofence-based speed limit" is a device-side setting. It is out of scope until RURA confirms it is allowed and the device behaviour is verified.

## 2. Data model (proposals — see spec §10.1)

- `vehicles.use_class`: `PRIVATE | PUBLIC_PASSENGER | GOODS | SCHOOL_BUS | OTHER`. A vehicle is **governed** when it has an active `governor_installations` row.
- `governor_installations`: vehicle, device, governor make/model/variant (catalogue), **set speed (km/h)**, RURA sticker serial, seal number, calibration date + technician, warranty start/end (≥ 12 months), owner's manual / technician's manual versions, status (`ACTIVE | SUSPENDED | REMOVED`). Every change is versioned (append-only history), because inspectors and RURA may ask what the set speed was on a given date.
- `governor_inspections`: date, inspector (technician or officer name), result (pass/fail + notes), evidence files, **next due date** (default +6 months, configurable).
- `governor_violations`: vehicle, start/end, peak speed, set speed at the time, duration, start/peak/end coordinates, source (`DEVICE_EVENT | COMPUTED`), alarm sent at, regulator delivery status.
- `governor_tamper_events`: type (`POWER_CUT | SPEED_SIGNAL_LOST | DEVICE_REMOVED | SEAL_BROKEN_REPORTED | JAMMING | OTHER`), start/end, evidence attribute, alarm sent at.
- `device_connectivity_periods`: device, online-from, online-to (closed when offline is detected), the source for quarterly reports. Never derive the quarterly report from logs or caches.
- `regulator_outbox`: event type, payload (Annex A format once known), status (`PENDING | SENT | ACKNOWLEDGED | FAILED`), attempts, last error, delivered at. Idempotent per violation.
- `regulator_access_grants`: regulator org, provider, scope (governed vehicles of that provider), granted by/at, revoked at.
- `compliance_reports`: provider, quarter, file, checksum, generated by/at. Immutable once issued; regenerate as a new version.

All rows carry `organization_id` and `provider_id` (see `gps-tenant-isolation`). Governor records are retained per RURA's rule (B14), even after a customer leaves its provider. Record the rule in an ADR.

## 3. Ingestion and detection

- Governed vehicles report **at least every 5 seconds** (RURA: "not more than five seconds interval"). The pipeline must handle this rate. 1,000 governed vehicles ≈ 200 positions/s, which is why the M3b scale proof matters for governor providers.
- Every stored record keeps the km/h speed and coordinates. Governor exports and reports display **dd/mm/yyyy** and **24-hour** time, whatever the user's locale.
- **Violation detection** has two sources:
  - Device events: limiting or overspeed alarms, if the model reports them (catalogue, B15).
  - Computed from records: speed above the set speed plus a tolerance (configurable; default 0, decided with RURA) for at least N consecutive records.

  Merge both sources into one violation episode. Do not open a new violation every 5 seconds.
- **Gaps in the record stream** of governed vehicles are themselves reportable. A gap longer than the threshold closes the connectivity period and raises an offline alarm. When buffered records arrive later, fill the history but keep the offline period (it really was offline for real-time purposes) and mark the records as delayed.
- **Tamper detection** uses catalogue-mapped attributes per model (e.g. external power voltage drop to 0, speed-signal input lost). If a model cannot report a tamper type, say so in the installation record and in reports. Never show "no tamper" when the device cannot detect it.

## 4. Alarms and SMS

- Violation and tamper → real-time alarm to the provider (in-app + email + SMS to the provider's on-call number) and entry in the regulator outbox.
- RURA requires an automated **SMS to the client** (the end customer) on changes, including the device going offline. Default triggers: offline, back online, tamper, installation status change, inspection due in 14 days, inspection overdue. Violations are a daily summary by default, configurable per customer.
- Governor SMS are compliance messages: they are not suppressed by quiet hours, and they use the platform allowance if the provider's SMS credits run out (record the cost for billing).

## 5. Quarterly report

Per provider and quarter, from `device_connectivity_periods`:
- each governed vehicle's total online time, offline time, number and longest offline periods
- violations and tamper counts
- inspection status

Output is PDF + XLSX in the provider's branding with platform attribution, and the format can be adjusted when RURA specifies one. The same input must always produce the same report: test this with fixed data.

## 6. Regulator portal and transmission

- Separate read-only shell (`/regulator/*`, platform-branded).
- Visible: governed vehicles of providers with an active `regulator_access_grants` row, their installations, inspections, violations, tamper events, connectivity and quarterly reports, plus live positions of governed vehicles only if RURA requires it.
- Not visible: anything about private vehicles or providers' commercial data.
- Every regulator request is audit-logged, and the provider can see the log.
- Regulator users are managed by a Regulator Administrator. Platform admins create the regulator organization and grants.
- **Transmission:** `RegulatorGateway` port with a `DevRegulatorGateway` adapter (labelled, refuses to load in production) until RURA provides the interface. The outbox gives retries, idempotency and delivery status, so switching to the real interface later changes only the adapter.

## 7. Compliance pack (for providers' RURA applications)

RURA asks suppliers to document their infrastructure, outsourced systems, access levels, backups, disaster recovery, incident management and QoS (availability, MTTR, uptime). Generate a document from platform configuration and monitoring covering:
- hosting location in Rwanda
- backup schedule and the last tested restore
- the DR plan and incident process
- measured uptime and MTTR for the period
- access-control and access-logging description
- list of sub-processors

Never claim numbers that are not measured.

## 8. Permissions (see `gps-rbac-permissions`)

`provider.governors.read`, `provider.governors.manage` (installation records), `provider.governors.calibrate` (record set-speed/calibration changes; technicians with a calibration authorisation only), `provider.governors.inspect`, `provider.compliance.reports`, `provider.compliance.regulator_outbox.read`, `customer.governors.read`, `regulator.read`, `regulator.users.manage`, `platform.regulators.manage`.

## 9. Tests

- Violation episodes: device-event-only, computed-only and both, all merged correctly. Boundary at exactly the set speed. Set-speed change mid-trip uses the value valid at each record's time.
- 5-second cadence ingestion for 100 simulated governed vehicles passes the steady-traffic smoke test.
- Offline gap → connectivity period closed, customer SMS sent once, buffered upload fills history without erasing the offline period.
- Tamper events only for models that support them; unsupported shows "not detectable".
- Quarterly report is reproducible and immutable once issued.
- Regulator sees only granted providers' governed vehicles. A private vehicle of the same customer is invisible (404). Every regulator call is in the audit log. Revoking a grant removes access immediately.
- Regulator outbox: idempotent per violation, retries with backoff, dev adapter refuses to load in production.
- No endpoint or job exists that changes a governor's set speed on a device.
